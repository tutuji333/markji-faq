# 如何更高效地批量制卡？

## 简答

论坛里目前最现实的路径，不是“在 App 里一次性把所有卡片随意批量改完”，而是：

- 先在外部整理原始文本
- 再用网页端批量制卡 / 导入
- 已建好的卡片，暂时按小批次修

如果你现在问的是“几百张现有卡片能不能一键批量改格式”，论坛里的较稳定口径仍然是：`完整能力还在路上`。

## 先分清你是哪一种“批量”

### 1. 导入前批量整理原始文本

这是当前最实用的一种。

- [topic 515](https://markji.discourse.group/t/topic/515) 里的官方邮件建议，就是先在外部用 AI 处理文本格式，再导入墨记。
- [topic 655](https://markji.discourse.group/t/topic/655) 里还有 Excel 工作流示例，适合问答卡这类规则清楚的内容。

如果你的需求是：

- 批量补空行
- 批量把正反面拼成统一格式
- 先把章节和文本结构理顺

那最省时间的做法通常都发生在“导入之前”，不是导入之后。

### 2. 网页端批量制卡

论坛里对网页端“简单模式 / 专业模式”的理解，目前比较接近下面这套：

- `简单模式`：更适合快速做一批基础卡片
- `专业模式`：更偏向定位、检查和更细的编辑辅助

但不要把“专业模式”理解成成熟的双向联动编辑器。

按 [topic 414](https://markji.discourse.group/t/topic/414) 和 [topic 421](https://markji.discourse.group/t/topic/421) 的讨论：

- 已经有人提到 `快速定位` 能力
- 但论坛里没有把它描述成真正的“左右完全联动 / 同步下滑 / 右侧直接批量改完”
- 如果你用了自定义分隔符，定位体验也可能不如预期

### 3. 已建好的卡片想批量修改

这正是很多人最想要、但目前最容易踩空的一块。

- [topic 515](https://markji.discourse.group/t/topic/515) 的官方邮件明确提到：`批量编辑` 和 `开放 API` 已在规划里。
- [topic 546](https://markji.discourse.group/t/topic/546) 的官方公告又再次把这两项放进了创作者能力路线图。

这意味着：

- 它们是明确方向
- 但你不该把它们当成现在已经成熟开放的现成功能

## 所以当前更稳妥的工作流是什么

如果你想把后续维护成本降下来，论坛材料比较支持下面这条路线：

1. 在外部保留一份 `原始文本 / Excel / AI 生成结果`
2. 在导入前把格式尽量整理好
3. 网页端负责最后一轮检查和少量修订
4. 不要把“后期大规模返工”当成默认能力来依赖

## 一句判断

- `导入前的大批量整理`：现在就能做，而且通常最好做
- `现有卡片的大规模批量改造`：目前仍更像路线图，不是稳定现成功能
