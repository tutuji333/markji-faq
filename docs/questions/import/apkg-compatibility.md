# 哪些 `.apkg` 更容易导入成功？

## 简答

论坛里目前最稳定的官方口径是：**当前导入更可靠的对象，是 Anki 的基础标准模板牌组。**

## 哪些情况更容易出问题

如果你的文件来自下面这些场景，失败概率通常会更高：

- 不是从标准 Anki 模板导出的牌组
- 用了很多个性化或复杂模板
- 文件来自别的记忆卡软件，再转成 `.apkg`

官方在论坛里已经明确说过：这类复杂模板并没有进一步的适配计划，不能保证导入成功。

## 如果你的文件来自 anymo 或其他软件

论坛里出现过一个用户 workaround：

- 先把源文件导入 `Anki`
- 再重新导出 `.apkg`
- 导出时勾选 `支持较旧的 Anki 版本`

这不是官方保证成功的方案，但论坛里确实有人靠这条路导入成功。

## 如果你的目标只是把内容迁过来

论坛里更稳定的官方建议还是这两条：

- 先去平台里搜有没有可替代牌组
- 把出问题的文件发给官方邮箱，作为兼容性研究样本

## 如果 `.apkg` 太大或一直导不进去

论坛里后来还出现过一种更明确的人工协助口径：

- 如果 `.apkg` 因为文件太大等原因没法正常导入，可以直接把文件发给官方邮箱 `support@markji.com`
- 官方有可能帮你把内容转成更适合导入墨记的格式，再回传给你处理后的文件
- 用户拿到处理后的文件后，常见做法不是继续导入 `.apkg`，而是先在墨记里新建牌组，再用 `批量制卡 -> 从文本导入`

不过这里也要提前有个预期：

- 这更接近 `人工协助处理`，不是说明复杂 `.apkg` 已经全部原生兼容
- 如果原文件里有截图、特殊模板或别的软件格式，处理后也可能仍然需要你手动补一部分内容
- 论坛里给出的邮件处理案例还特别提醒过：导入文本时，卡片分隔语法可能需要改成 `===`
